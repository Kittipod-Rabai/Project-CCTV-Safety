# สาธิตด้วยหน้าจอจริงและข้อมูลที่เชื่อมกัน

อัปเดต: 14 ตุลาคม 2026 — ต่อยอดโหมดสาธิต commit `9f1b16c`

## สิ่งที่เปลี่ยน

Dashboard, Live, Logs/modal, ศูนย์แจ้งเตือน, Analyze และ Settings ใช้ DOM และตัวแสดงผลชุดเดียวกับโหมดจริงแล้ว ไม่สร้างหน้าสาธิตแยกหรือจอมอนิเตอร์หลายกล้อง ผู้พัฒนาระบบคือ AEGIVIS; โรงงาน/คลังสินค้าเป็นบริบทสมมติของสถานที่ติดตั้ง ไม่ได้อ้างว่าเชื่อมกล้องจริง

`RealProvider` ใช้ API เดิมผ่าน transport ที่ตรวจ mode generation ส่วน `DemoProvider` ใช้ memory store และสื่อ local เท่านั้น ไม่มีการแทนที่ global fetch, เปลี่ยน API/schema หรือเขียนข้อมูลเดโมลง SQLite

ข้อมูลตั้งต้นเป็น **สถานการณ์สมมติทั้งหมด**: 28 รอบใน 7 วัน กระจาย 3/4/2/5/3/4/7 รอบ วันและเวลาของรอบเลื่อนตามวันที่เปิดเดโมใน Bangkok ยอดรายการ/ประเภท/สถานะ/กราฟ/การแจ้งเตือนคำนวณจากข้อมูลจริงใน memory store ไม่ใช้ตัวเลขยอดรวมที่กรอกแยก กรณีไม่พบผลยังมีรอบวิเคราะห์แต่ไม่มีแถวผล

มีทั้ง PPE ครบ/ไม่ครบ, Fall, Smoke/Fire, Fight, Non-fight, Fall/Fight กำกวม, ไม่พบผล และ Smoke ต่ำกว่าเกณฑ์แจ้งเตือน กรณีสมมติใช้ภาพวาดและคะแนนกำหนดไว้ ไม่ใช่ผลโมเดล

## เตรียมสื่อจริงในเครื่อง

รันจาก root ของโปรเจกต์:

```powershell
.\.venv-test\Scripts\python.exe scripts/prepare_demo_assets.py
.\.venv-test\Scripts\python.exe -m uvicorn webapp.api:app --host 127.0.0.1 --port 8000
```

เปิด `http://127.0.0.1:8000/` แล้ว Ctrl+F5 คำสั่งเตรียมสื่ออ่านผลที่มีอยู่ ไม่ inference/ฝึกโมเดลใหม่ ต้องมี `reports/settings_verification/real-defaults.json` และภาพ D-Fire ต้นทางในเครื่อง หากย้ายเครื่องให้เตรียมชุดไฟล์ local เดิม ไม่มี dataset หรือ JPEG/base64 ของ dataset ถูกเพิ่มลง Git

Manifest ที่ติดตามใน Git อยู่ที่ `mockup/demo-manifest.json` ระบุ hash ต้นทาง/รายงาน/ผล JSON/preview, โมเดล, อุปกรณ์และ Settings เดิม ไฟล์จริงอยู่ใน `mockup/demo-assets/` ซึ่ง ignore ทั้งโฟลเดอร์

ภาพที่ใช้คือ D-Fire `WEB11091.jpg` ขนาด 640×360 ผล YOLOv8n CPU ที่บันทึกไว้:

- Smoke **0.8779**, กล่อง `[18.5806, 3.7186, 640, 351.5354]`
- Fire **0.3589**, กล่อง `[232.5107, 233.4174, 261.959, 252.1475]`

Preview ถูกตรวจด้วยสายตาแล้วเป็นควัน/พืชพรรณ ไม่มีบุคคลที่ระบุตัวได้ ไม่ได้อ้างว่าเป็นภาพโรงงานจริงหรือว่าได้รันการตรวจใบหน้าใหม่ ใช้ภาพนี้ประกอบโซนคลังสมมติเท่านั้น รายงานต้นทางไม่ได้เก็บเวลารัน จึงแสดงว่าไม่ได้บันทึกเวลาเดิมและไม่ใช้เวลาแก้ไขไฟล์แทนเวลารัน

ระบบตรวจ checksum และความครบของผลก่อนสร้างรอบ ถ้าสื่อหาย ผิด hash หรือ preview ไม่ได้รับการตรวจ จะบอกข้อผิดพลาด ไม่เปิดภาพดิบ ไม่แทนด้วยผลสุ่ม และไม่เรียก backend จริงแทน ยังเลือกกรณีสมมติได้ ดูขอบเขตที่มาของภาพใน `docs/stage1_dataset_primary_source_audit.md`

## ลำดับพรีหลักประมาณ 90 วินาที

1. หยุด Live จริงให้จบ แล้วกด **เข้าโหมดสาธิต** เลือก **คลังสินค้า · Smoke/Fire · ผลบันทึกจริงจากภาพนิ่ง**
2. เปิด Live แล้วกด **เริ่ม Live** มีแหล่งภาพเดียว ตัวเลือกไฟล์/RTSP จริงถูกซ่อน และอุปกรณ์ระบุว่าไม่ได้รันโมเดล
3. วินาที 10 แสดงภาพนิ่งเล่นซ้ำและคะแนนเดิม สร้างผล Smoke/Fire แต่แจ้งเฉพาะ Smoke เพราะ Fire ต่ำกว่าเกณฑ์แจ้ง .5
4. กด **พักสถานการณ์** แล้วเปิด popup/ศูนย์แจ้งเตือนไป Logs ดูที่มา กล่อง คะแนน จำนวน observations และรับทราบรายการ Smoke
5. เปิด Dashboard เพื่อดูรอบ/รายการ/รอตรวจสอบที่มาจากชุดข้อมูลเดียวกัน
6. กด **เหตุการณ์ถัดไป** เพื่อไปวินาที 20: ผลซ้ำเพิ่ม observations ในแถวเดิม ไม่เพิ่มแถวและไม่แจ้งซ้ำใน cooldown
7. ไปวินาที 45: หากยังรอตรวจสอบจะแจ้งซ้ำได้ แต่ถ้ารับทราบ/ปิดแล้วจะไม่แจ้ง สามารถใช้ปุ่มเปิดใหม่ใน Logs ทดลองได้ การเปิดใหม่เพียงอย่างเดียวไม่สร้างแจ้งเตือน
8. วินาที 90 จบเซสชัน ประวัติยังอยู่ กด **เริ่มสาธิตใหม่** คืนประวัติ/Settings/นาฬิกาตั้งต้น หรือ **กลับโหมดจริง** เพื่อโหลดข้อมูลจาก API ใหม่

ตัวเล่นทำงานต่อเมื่อสลับหน้า แต่พักนาฬิกาเมื่อแท็บถูกซ่อนและไม่เร่งชดเชยเวลาที่หายไป ปุ่มเหตุการณ์ถัดไปใช้ได้แม้พักอยู่ เวลาในแถบเป็น **เวลาสถานการณ์** แยกจากเวลาในคลิป; ภาพนิ่งมีเวลาในสื่อเป็น null ไม่ปลอมเป็นคลิปจริง 90 วินาที

## Analyze และ Settings

เลือกสถานการณ์บนแถบเดียวกันแล้วกดวิเคราะห์ในหน้า Analyze ใช้กราฟ/ตาราง PPE/กรอบภาพ/Stage 2/รายละเอียดเทคนิคเดิม กรณีวิดีโอสมมติแสดง sparse frame ภาพวาดและหน้าต่างผล ไม่สร้าง privacy.complete หรือ dense video ที่ไม่มีหลักฐาน

การวิเคราะห์เพิ่มรอบและผลลง memory store เดียวกับ Live ค่าเริ่มต้นใช้ Settings ที่บันทึกในเดโม หรือยกเลิก checkbox เพื่อ override เฉพาะรอบ ป้าย revision คือ snapshot ตอนเริ่ม แม้บันทึกใหม่ระหว่าง Live ผลที่กำลังเล่นยังใช้ค่าเดิม

YOLO ใช้การเปรียบเทียบคะแนน ≥ threshold; X3D ใช้ Fight > threshold กฎ PPE ใช้ตำแหน่งอุปกรณ์และ person confidence เช่นระบบจริง ค่า IoU/imgsz/max_det/Tracking แสดงเป็นค่าที่ตั้งไว้ แต่ไม่อ้างว่า inference ใหม่หรือแต่งคะแนนใหม่ ค่าที่ใช้รันหลักฐานเดิมแสดงแยกจากค่าที่ใช้กรองเดโม

ทดสอบง่าย: ตั้ง Smoke/Fire เป็น .95 แล้ววิเคราะห์ภาพหลัก จะไม่มีสองกล่องดังกล่าวในผลรอบถัดไป กดเริ่มสาธิตใหม่คืนค่า .2 เดโมนี้ไม่มีค่า FPS/latency ที่วัดใหม่; หากไม่มีในหลักฐานแสดง **ไม่ได้วัด** อุปกรณ์ CPU เป็นข้อมูลจากรอบที่บันทึก ไม่ใช่อุปกรณ์ที่กำลังประมวลผล

เมื่อสลับโหมด จะคืนตัวเลือกโมเดล/อุปกรณ์เดิมและโหลด Settings ของโหมดปลายทางใหม่ บังคับใช้ค่าที่บันทึกเป็นค่าเริ่มต้นเพื่อไม่ให้ override ในฟอร์มข้ามโหมด ข้อมูลเดโมไม่เขียนลงฐานจริง รีเฟรชกลับโหมดจริงเสมอ
