# ผลตรวจงาน 4 — แจ้งเหตุสงสัยภายในเว็บ

วันที่ตรวจ: 14 ตุลาคม 2026

**สถานะ: ทำงานจริงระดับต้นแบบบนเครื่องทดสอบแล้ว**

เส้นทางที่ตรวจ: ผลเข้าเกณฑ์จากโมเดล บันทึกการแจ้งเตือนพร้อมประวัติ แสดง popup/แผงแจ้ง เปิด OBS ที่เกี่ยวข้อง และบันทึกรับทราบใน Logs

## สิ่งที่ทำแล้ว

- เพิ่มตาราง notifications และย้ายฐานข้อมูล v1 เป็น v2 อัตโนมัติ รักษาประวัติและสถานะเดิม โดยไม่สร้างแจ้งย้อนหลังจากข้อมูลเก่า
- บันทึกการแจ้งเตือนใน transaction เดียวกับผลตรวจจับ หากบันทึกไม่ได้ให้ rollback และแจ้ง error
- ใช้คะแนนของผลปัจจุบันตามเกณฑ์ ไม่ใช้คะแนนสูงสุดเก่ามากระตุ้นการแจ้งใหม่
- เว้น 30 วินาทีต่อรายการประวัติ run/type/model ใช้เวลาประมวลผลจริงและคงอยู่หลัง restart รองรับ worker ที่เขียนพร้อมกัน
- หยุดแจ้งซ้ำของแถวที่รับทราบ/ปิดแล้วจนผู้ใช้เปิดกลับและมีผลเข้าเกณฑ์ใหม่
- เพิ่ม GET /api/notifications พร้อม cursor เพื่ออ่านรายการใหม่เป็นชุด ไม่ส่งแถวเดิมทุกครั้ง
- เพิ่มปุ่มเหตุสงสัย แผงล่าสุด 20 รายการ และ popup เหตุสงสัยที่รอตรวจสอบ พร้อมปุ่มเปิดประวัติจริงใน Logs
- หน้าเว็บ poll ทุก 2 วินาทีขณะเปิดอยู่ เมื่อ reload โหลดประวัติโดยไม่แสดง popup เก่าซ้ำ มีสถานะว่าง/error และคง focus เมื่อข้อมูลไม่เปลี่ยน

## เงื่อนไขและข้อจำกัด

- Fall, Fire, Smoke, no_helmet/no_vest และ Fall/Fight conflict ต้องมีคะแนนอย่างน้อย 0.5 ส่วน Fight อย่างน้อย 0.7
- ไม่แจ้งจาก Person, Helmet, Vest หรือ Non-fight คะแนน PPE เป็น person confidence ประกอบกฎ ไม่ใช่ความน่าจะเป็นว่าไม่สวมอุปกรณ์
- เกณฑ์เป็น heuristics ระดับ pilot ยังไม่ได้ประเมินความแม่นยำของระบบแจ้งเตือนกับกล้องเป้าหมาย ผลผิดพลาดหนึ่งเฟรมยังอาจสร้างแจ้งได้
- Cooldown ไม่ใช่การแยกเหตุจริง หากผลต่อเนื่องเกิน 30 วินาทีอาจแจ้งใหม่ และการวิเคราะห์ซ้ำสร้าง run ใหม่ที่มี gate แยกกัน
- ช่วงพักอิงเวลาบันทึก ไม่ใช่เวลาในวิดีโอ วิดีโอที่ประมวลผลเร็วอาจรวมหลายช่วงไว้ในการแจ้งครั้งเดียวต่อแถวสรุป
- จำนวนบนปุ่มคือรายการแจ้งทั้งหมดที่บันทึก ไม่ใช่จำนวนที่ยังไม่อ่านหรือจำนวนเหตุที่ยืนยัน การซ่อน popup ไม่เปลี่ยนสถานะประวัติ
- ไม่มี browser Push, เสียง, email, SMS หรือ LINE เมื่อปิดหน้าเว็บจะไม่มี popup แต่ backend ที่กำลังวิเคราะห์ยังบันทึกการแจ้งไว้ได้

## ผลทดสอบอัตโนมัติ

- ชุดทดสอบรวม **299 passed, 0 failed, 0 errors, 0 skipped** ใช้เวลาประมาณ 42.48 วินาที มี deprecation warnings เดิมจาก dependencies
- ผลซ้ำ 100 ครั้งในเวลาเดียวกันแจ้งเพียงครั้งเดียว ก่อนครบ 30 วินาทีไม่แจ้งเพิ่ม และเมื่อครบช่วงพักจึงแจ้งได้
- ตรวจคะแนนต่ำหลังคะแนนสูงว่าไม่ใช้ historical maximum มาแจ้งซ้ำ
- ตรวจสถานะ ack/closed/reopen และเปิด EventStore ใหม่ว่ายังใช้ cooldown เดิม
- ตรวจ worker เขียนพร้อมกัน 25 ครั้งได้การแจ้งหนึ่งรายการ
- ตรวจ migration จาก schema v1 ว่าประวัติ/สถานะ/audit ยังอยู่ และไม่มีแจ้งย้อนหลัง
- ตรวจ rollback เมื่อ notification insert ล้มเหลว รวมปฏิเสธ schema ที่ไม่รองรับ
- ตรวจ cursor 55 รายการแบบแบ่งชุด ไม่มีแถวหายหรือซ้ำ และตรวจ query ที่ไม่ถูกต้อง/SQLite ใช้ไม่ได้
- ตรวจเส้นทาง Stage 1, Pipeline และ Live ด้วยผลควบคุมที่เข้าเกณฑ์ แล้วเปิด OBS จริงผ่าน API และตรวจข้อมูลหลัง restart
- JavaScript syntax และ git diff --check ผ่าน

## ผลผ่านโมเดลจริงและ browser

- ใช้ YOLOv8n บน CPU กับภาพ D-Fire test WEB11091.jpg ที่มีในเครื่อง พบ Smoke 0.8779 และ Fire 0.3589 จึงแจ้ง Smoke หนึ่งรายการตามเกณฑ์ ไม่ใช้ผลนี้เป็นหลักฐานว่าระบบแจ้งถูกทุกกรณี
- หน้าเว็บแสดง popup “สงสัยควัน … รอตรวจสอบโดยผู้ใช้” และแผง NT-1 เปิด OBS-1 ใน Logs ได้ตรงกับไฟล์/โมเดล/คะแนน
- กดรับทราบ OBS-1 ผ่าน browser สำเร็จ แผงแจ้งแสดงสถานะประวัติที่อ่านล่าสุดเป็นรับทราบแล้ว
- สร้าง continuous-smoke.avi จากภาพเดิม 35 เฟรมที่ 5 FPS ใน reports เพื่อทดสอบผลต่อเนื่องด้วยน้ำหนักจริง ไม่ใช้เป็นชุดประเมินความแม่นยำหรือกล้องสด
- Live ประมวลผลครบ 35 เฟรม พบ Smoke 35 observations แต่บันทึกแจ้งเพียงหนึ่งรายการในช่วงพัก Popup ของ Live เปิด OBS-3 ได้โดยตรง
- มีรายการแจ้งทั้งหมด 2 รายการจาก 2 runs เป็น NT-1 ของภาพและ NT-2 ของ Live ไม่ใช่สองเหตุจริงที่ยืนยันแล้ว
- จำลองฐานข้อมูลใช้ไม่ได้: API คืน 503 แผงแจ้งแสดง error และจำนวนเป็น “—” พร้อมระบุว่ารายการเก่าเป็นข้อมูลที่อ่านได้ครั้งก่อน
- เปิด backend ใหม่ด้วยฐานเดิม: JSON การแจ้งเตือนตรงกับก่อน restart และอ่านหลัง cursor ล่าสุดได้รายการว่าง หน้าเว็บ reload แล้วไม่ popup รายการเก่า
- ไม่พบ JavaScript warning/error ในรอบ browser ปกติ ข้อผิดพลาด 503 ในรอบจำลองเป็นสิ่งที่ตั้งใจให้เกิด
