# บันทึกแผนแก้ไข 5 งานก่อนนำเสนอครั้งสุดท้าย

วันที่บันทึก: 14 ตุลาคม 2026

สถานะ: งาน 1–3 ดำเนินการและตรวจสอบแล้วบนเครื่องนี้; งาน 4–5 ยังไม่เริ่ม

เป้าหมาย: ต่อส่วนทดลองและส่วนจำลองให้เป็นฟังก์ชันที่ทำงานจริงและมีหลักฐานทดสอบ สำหรับการนำเสนอ Project CCTV Safety ครั้งสุดท้าย การผ่านแต่ละงานยังไม่ใช่การรับรองระบบระดับ production

เอกสารประกอบ: [เนื้อหาสไลด์](slides.md) · [บทพูด](speaker-notes.md) · [หลักฐานและสถานะงาน](evidence.md)

## 1. Pipeline รวมและ Live replay

- [x] ทดสอบตั้งแต่เลือกไฟล์บนเว็บ → API → YOLO/X3D → แสดงผล
- [x] แก้จุดขัดข้องที่พบ รวมการเปลี่ยนไฟล์ ผลเก่าค้าง และการแสดง error
- [x] ทดสอบ Live replay ตั้งแต่เริ่มจนจบ รวมการหยุดและเริ่มใหม่
- [x] เก็บผลทดสอบ ภาพหน้าจอจากเดโม และเวลาประมวลผลจากเครื่องจริง (ใช้ภาพหลักฐานแทนคลิปบันทึกหน้าจอ)

เกณฑ์เสร็จ: เส้นทางหลักผ่านการทดสอบครบบนเครื่องที่ใช้พรี มีหลักฐานตรวจสอบได้ และระบุชัดว่าเป็น replay ไม่ใช่กล้อง RTSP สด

## 2. Alert / Logs จากผลจริง

- [x] เพิ่มการบันทึกผลตรวจจับลง SQLite ในเครื่อง
- [x] เก็บแหล่งไฟล์/เซสชัน เวลาในวิดีโอ ประเภทผล โมเดล และคะแนน
- [x] ให้หน้า Logs อ่านข้อมูลจริงแทนรายการสุ่ม พร้อมตัวกรองและแบ่งหน้า
- [x] บันทึกสถานะรอตรวจสอบ / รับทราบ / ปิดรายการ
- [x] ตรวจว่าปิดและเปิดโปรแกรมใหม่แล้วประวัติยังอยู่

เกณฑ์เสร็จ: ผลจากการวิเคราะห์สร้างประวัติจริงที่เรียกดูและเปลี่ยนสถานะได้ โดยไม่ถือว่าผลโมเดลทุกแถวเป็นเหตุจริงที่ยืนยันแล้ว

## 3. Dashboard จากข้อมูลจริง

- [x] เชื่อม Dashboard กับข้อมูลที่บันทึกจากงาน 2
- [x] แสดงจำนวนรายการแยกประเภท รายการรอตรวจสอบ และผลล่าสุด
- [x] แสดงกราฟโดยระบุชัดว่าใช้เวลาวิเคราะห์/บันทึก หรือเวลาในวิดีโอ
- [x] แสดงสถานะเซสชันจริง และเลิกใช้จำนวนกล้อง/สถานะกล้องจำลองเป็นข้อมูลจริง
- [x] ตรวจกรณีไม่มีข้อมูลและกรณีเรียกข้อมูลไม่สำเร็จ

เกณฑ์เสร็จ: ตัวเลขและกราฟตรงกับประวัติจริง เมื่อไม่มีข้อมูลแสดงสถานะว่าง ไม่เติมข้อมูลสุ่ม

## 4. แจ้งเตือนภายในเว็บ

- [ ] กำหนดเงื่อนไขจากผลตรวจจับสำหรับแจ้งเหตุสงสัย
- [ ] แสดงข้อความแจ้งเตือนภายในเว็บ และกำหนดช่วงพักเพื่อลดการแจ้งซ้ำ
- [ ] ใช้ข้อความว่าเป็นเหตุสงสัยที่รอตรวจสอบ
- [ ] เชื่อมรายการแจ้งเตือนไปยังประวัติในงาน 2
- [ ] ทดสอบว่าผลต่อเนื่องจากเหตุเดียวกันไม่สร้างแจ้งเตือนทุกเฟรม

เกณฑ์เสร็จ: ผลที่เข้าเงื่อนไข → แจ้งบนเว็บ → บันทึกและเปิดดูประวัติได้ครบ พร้อมหลักฐานทดสอบการลดรายการซ้ำ

## 5. หน้าตั้งค่าระบบที่ใช้จริง

- [ ] ทำหน้าปรับค่าที่ backend รองรับ เช่น confidence threshold และ Fight threshold
- [ ] ตรวจค่าก่อนบันทึกและเก็บค่าที่เลือกไว้
- [ ] ให้การวิเคราะห์ครั้งถัดไปใช้ค่าที่บันทึกจริง
- [ ] ทดสอบการโหลดค่ากลับหลังเปิดโปรแกรมใหม่ และการปฏิเสธค่าที่ไม่ถูกต้อง

เกณฑ์เสร็จ: ผู้ใช้แก้และบันทึกค่าได้ โดยตรวจยืนยันจากค่าที่ backend ใช้ในการวิเคราะห์ ไม่ใช่เปลี่ยนเฉพาะข้อความบนหน้าจอ

## ลำดับดำเนินงานและการติดตาม

- ทำงาน 1 → 2 → 3 → 4 เป็นลำดับหลักสำหรับเดโมครบกระบวนการ แล้วทำงาน 5
- งาน 1–3 ผ่านการตรวจบนเครื่องนี้แล้ว เหลืองาน 4–5 โดยทำการแจ้งเตือนก่อนงานตั้งค่า
- ทำเครื่องหมายเสร็จเฉพาะรายการที่ตรวจแล้ว พร้อมเพิ่มลิงก์หลักฐานทดสอบ
- เมื่อทำงานเสร็จ ให้ปรับ slides.md, speaker-notes.md และ evidence.md ให้ตรงกับผลจริง ไม่เปลี่ยนสถานะล่วงหน้า
- บันทึกนี้ไม่ได้สั่งเริ่มฝึกโมเดลใหม่ ทดสอบกล้อง RTSP จริง พัฒนาหลายกล้อง หรือเชื่อมบริการแจ้งเตือนภายนอก
