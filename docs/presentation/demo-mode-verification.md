# โหมดสาธิตทั้งเว็บ

อัปเดต: 14 ตุลาคม 2026

## วิธีใช้ตอนนำเสนอ

1. เปิดเว็บผ่าน backend ตามคำสั่งใน `mockup/README.md` เว็บเริ่มเป็นโหมดจริง
2. หยุด Live จริงให้จบ แล้วกด **เข้าโหมดสาธิต** บนแถบด้านบน
3. ใช้เมนูเดิมเปิด Dashboard, Live, Alerts / Logs, Upload & Analyze และ Settings แถบสีเหลืองระบุข้อมูลจำลองทุกหน้า
4. Dashboard และ Logs ใช้รายการตัวอย่าง 24 รายการร่วมกัน ค้นหา กรอง เปลี่ยนหน้า เปิดรายละเอียด รับทราบ/ปิดรายการได้ ยอดและเหตุสงสัยตัวอย่างอัปเดตตรงกัน
5. หน้า Live กด **เริ่มการสาธิต / หยุดการสาธิต** เพื่อแสดงฉากวาด คะแนน และ Event Stream ตัวอย่าง ไม่มีการเปิดกล้องหรือเรียกโมเดล
6. หน้า Analyze เลือกตัวอย่างภาพหรือวิดีโอแล้วกดแสดงผลจำลอง กรอบและคะแนนกำหนดไว้เพื่ออธิบาย UI ภาพ preview เป็นภาพวาดประกอบ ไม่ใช่คลิปหรือผล inference จริง ไม่รับไฟล์ผู้ใช้ในโหมดนี้
7. หน้า Settings บันทึกค่าจำลองในหน่วยความจำได้ เกณฑ์ Fight ที่บันทึกมีผลกับการแสดงผลวิดีโอตัวอย่างรอบถัดไป ส่วนตัวเลือกอื่นใช้สาธิตฟอร์ม ไม่ได้ประมวลผลโมเดล
8. กด **กลับโหมดจริง** เพื่ออ่านข้อมูลจริงใหม่ ข้อมูลเดโมถูกล้างเมื่อออกจากโหมด รีเฟรชเว็บกลับโหมดจริงเสมอ

การสาธิต UI ไม่ใช่หลักฐานว่าโมเดลตรวจเหตุได้ถูกต้อง ตอนแสดงผลโมเดลจริงต้องกลับโหมดจริงและใช้ภาพ/คลิปจริงแยกต่างหาก

## การแยกข้อมูล

- ไม่มีการเปลี่ยน API หรือ schema ฐานข้อมูล ใช้ชุดข้อมูล frontend แยกและรหัส `DEMO-`
- ก่อนเข้าเดโมตรวจ `/api/live/status` ถ้า starting/running/degraded/stopping หรืออ่านสถานะไม่ได้ จะคงโหมดจริงและแจ้งเหตุผล
- ปุ่มสลับถูกล็อกระหว่างการวิเคราะห์และการบันทึกจริง รวมทั้งการเปลี่ยนสถานะประวัติ
- คำขออ่านที่ค้างถูก abort และตรวจรุ่นของโหมดเพื่อปฏิเสธผลตอบกลับเก่า ตัวควบคุมหน้าจริงหยุดเรียก API ระหว่างเดโม
- กลับโหมดจริงแล้วโหลด Dashboard, Logs, Settings, health และรายการแจ้งใหม่ ปิด popup และ timer เดโม ไม่บันทึกเดโมลง SQLite หรือ localStorage

## ผลตรวจ

- Node tests ใหม่ 10 กรณีผ่าน: สถานะ Live ที่ต้องหยุดทั้ง 4 สถานะ, สถานะผิดรูป/เครือข่ายล้มเหลว, ปฏิเสธคำขอจริงทุก method ในเดโม, ผลอ่านตอบกลับช้า, ล็อกระหว่างเขียน/วิเคราะห์, คืนล็อกเมื่อผิดพลาด และ HTTP 204
- Python regression ที่เกี่ยวข้องผ่านครบ 206 กรณี รวม frontend static 38 กรณีและ API smoke ที่ใช้ weights จริง (JUnit: `reports/demo_verification/pytest.xml`)
- ตรวจเบราว์เซอร์บน backend พอร์ต 8019 ด้วย SQLite แยกที่ `reports/demo_verification/history.sqlite3`: ครบทุกหน้า ค้นหา/กรองประเภทผล เปลี่ยนสถานะแล้ว Dashboard และเหตุสงสัยเปลี่ยนตรงกัน บันทึก Fight threshold จำลองแล้วผลตัวอย่างเปลี่ยนตาม
- ตรวจเข้าเดโมด้วยคีย์บอร์ด, เริ่ม/หยุด Live จำลอง, สลับกลับข้อมูลจริงและรีเฟรชคืนโหมดจริง รวมทั้งขนาดจอ 390 × 844 และจอคอม
- SQLite dump ก่อน/หลังการโต้ตอบเดโมมี SHA-256 เท่ากัน: `a6c4594b632c344112aa22ed34e509692b39c014b609b1a06a41d9ce816aa615` ตาราง runs/observations/status audit/notifications/settings ไม่เพิ่มข้อมูล ค่าจริงยัง revision 0 ในฐานทดสอบ
- หลักฐานฐานข้อมูลและภาพหน้าจออยู่ใน `reports/demo_verification/` ซึ่งถูก ignore ตามนโยบายเดิม

