# AEGIVIS — AI-Powered Safety Shield


> **ชื่อโครงการ:** Project CCTV Safety · **แบรนด์ระบบ:** AEGIVIS — AI-Powered Safety Shield
> **สถานะ (2026-10-15):** Educational pilot — โหมดจริงสรุปประวัติจาก SQLite; โหมดสาธิตใช้ UI ร่วมกันและข้อมูลแยกในหน่วยความจำ
> ส่วน Upload & Analyze และ Live replay เรียกโมเดลจริง และ Alert / Logs อ่านประวัติผลโมเดลจาก SQLite ผ่าน backend แล้ว
> มีหน้าตั้งค่า YOLO/X3D/Tracking ที่บันทึกจริง มีการบันทึกรับทราบ/ปิดรายการ และแจ้งเหตุสงสัยภายในเว็บพร้อม cooldown แต่ไม่ใช่การยืนยันเหตุ ไม่ได้ส่งแจ้งเตือนภายนอก และยังไม่มีระบบบัญชีผู้ใช้
> ปุ่ม **เข้าโหมดสาธิต / กลับโหมดจริง** แยกชุดข้อมูลตัวอย่างครบทุกหน้าจากระบบจริง ใช้หน้าจอชุดเดียวกับระบบจริง พร้อม Live แหล่งภาพเดียวและชุดข้อมูลเชื่อมกัน
> ดู [หลักฐานงาน 2](../docs/presentation/history-verification.md) และ [หลักฐาน Dashboard](../docs/presentation/dashboard-verification.md)
>
> **หมายเหตุ Schema:** โหมดสาธิตใช้ประเภทผลเดียวกับระบบจริง: detector schema v2 มี 6 spatial classes, `no_helmet`/`no_vest` เป็นกฎ PPE, `fight`/`non_fight` เป็นผล temporal และมีสถานะ Fall/Fight กำกวม แยกป้ายผลบันทึกจริงและสถานการณ์สมมติ ดู `../docs/project_status.md`

##  หน้าจอที่มีใน Mockup

- **Dashboard:** จำนวนแถวสรุปผลโมเดล รอตรวจสอบ รอบวิเคราะห์ ผลล่าสุด และกราฟรายวันจาก SQLite พร้อมสถานะเซสชันจาก Live API ดูรายละเอียดเวลา/หน่วยนับในหัวข้อด้านล่าง
- **Live CCTV Monitoring:** โหมดจริงเรียก Live replay ด้วยโมเดลจริง; โหมดสาธิตใช้ preview แหล่งเดียวและข้อความ Live รูปแบบเดียวกัน ส่วน RTSP ยังไม่ยืนยันกับกล้องจริง
- **Alert / Logs:** ประวัติผลตรวจจับจริงจาก SQLite พร้อมค้นหา ช่วงเวลาบันทึก แหล่งไฟล์ ประเภทผล สถานะตรวจสอบ แบ่งหน้า และ audit การเปลี่ยนสถานะ ไม่เก็บภาพ/คลิป
- **Upload & Analyze:** วิเคราะห์ภาพ/วิดีโอด้วย YOLO/X3D ผ่าน API

หน้า **จัดการกล้อง** ยังเป็นเมนูที่ปิดไว้ ส่วน **ตั้งค่าระบบ** บันทึกค่า YOLO/X3D/Tracking ผ่าน backend ได้แล้ว

### หน้า Upload & Analyze (`#v-analyze` + `analyze.js`) — plan sections 9.2–9.4

- **อินพุต:** เลือกไฟล์ (`.jpg .jpeg .png .bmp .webp .mp4 .avi .mov .mkv`, ≤ 100 MB) และโมเดล Stage 1
  (`yolov8n` / `yolov8s`) แล้วกด Analyze — preview ย่อเป็น thumbnail หลังวิเคราะห์ (object URL ถูก revoke เมื่อเปลี่ยนไฟล์)
- **ทุกอย่างมาจาก response ของการวิเคราะห์ครั้งปัจจุบันเท่านั้น:** เลือกไฟล์ใหม่หรือกด Analyze ใหม่จะล้างผลเดิมทั้งหมด
  (สรุป, chip, ตาราง PPE, canvas, ไทม์ไลน์, รายละเอียดทางเทคนิค) และ response ของรอบเก่าที่มาช้าจะถูกทิ้ง;
  ถ้า Stage ใด error จะไม่มีผลเก่าค้าง ตัวกรองการแสดงผลกลับเป็นค่าเริ่มต้นทุกครั้ง
- **วิดีโอ — ตรวจว่าเบราว์เซอร์เล่นได้ไหม (probe):** `<video>` preview ต้องเกิด `loadeddata` และมี `videoWidth > 0` ภายใน 6 วินาที
  - เล่นได้ → pipeline เรียก Stage 1 `mode=dense` (`sample_fps` 1–30, ค่าเริ่มต้น 10) และ Stage 2 ในคำขอเดียว
    องค์ประกอบวิดีโอต้นฉบับถูกซ่อนและวาดลง canvas แบบ opaque; ทุกเฟรมที่แสดงต้องผ่าน face mask จาก YuNet แล้วจึงวาดกล่อง
    ถ้าขั้นตอน anonymization หรือการวาดล้มเหลว canvas จะไม่แสดงภาพต้นฉบับ
    วาดกล่องของตัวอย่าง dense ที่ใกล้ `currentTime` ที่สุด (เฉพาะถ้าห่างไม่เกิน `1/sample_fps`), คำนวณกรอบภาพจริงตาม
    `object-fit: contain` และวาดใหม่เมื่อ resize / seek / ระหว่างเล่น; มุมขวาบนแสดง "Stage 2: ทะเลาะ / ปกติ" (ไม่มีเวลา)
  - เล่นไม่ได้ (เช่น mp4 `mp4v` จาก OpenCV) → Stage 1 `mode=frames` (`max_frames` 1–60, ค่าเริ่มต้น 16) แสดงภาพทีละเฟรม
    และบอกเหตุผล; ถ้า dense ตอบ `video_too_long` จะลองใหม่แบบ `frames` อัตโนมัติ
- **ไทม์ไลน์เส้นเดียว (9.4.1):** ใต้ภาพมีแถบแบบ slider "▶ ‹ ก่อนหน้า ─●─ ถัดไป ›" — วิดีโอที่เล่นได้ แถบนี้ **คือแถบเลื่อนเวลา**
  ของวิดีโอ (ลาก/คลิกเพื่อ seek, หัวเลื่อนตามการเล่น, ปุ่มก่อนหน้า/ถัดไป = ±1 ตัวอย่าง); โหมด frames แถบนี้คือ slider เลือกเฟรม;
  ช่วงที่ Stage 2 ให้ label `fight` แสดงเป็น **แถบแดง** บนเส้น (`<input type="range">` จึงใช้คีย์บอร์ดได้)
- **Stage 2:** แสดงเพียง "⚠ พบการทะเลาะ" หรือ "✓ ไม่พบการทะเลาะ" (จาก `summary.fight_windows`);
  เวลาแต่ละช่วง, label, ความน่าจะเป็นดิบ, `max_fight_prob` และ `fight_windows / total_windows` อยู่ใน "รายละเอียดทางเทคนิค"
- **Stage 1 สรุปสั้น:** แสดงจำนวนเป็น "กล่อง person สูงสุด N กล่อง/เฟรม" ไม่อ้างเป็นจำนวนบุคคลจริง เพราะไม่มี tracking ที่ยืนยันอัตลักษณ์และกล่องซ้ำอาจทำให้จำนวนเกินจริง; PPE เป็นผลที่คำนวณจากกล่องเหล่านี้ ส่วน Fall/Fire/Smoke เป็นสัญญาณจากโมเดลที่ต้องตรวจทาน
- **มุมมอง (9.4.8):** ตัวเลือก "แสดงผล: มุมมอง PPE | เลือก class" — ถ้า response มีคน เปิดที่ **มุมมอง PPE** เป็นค่าเริ่มต้น
  (กล่องคนสีเขียว = ไม่มี alert / แดง = มี alert, หมายเลข #i ตรงกับตาราง PPE, สีมาจาก `ppe` rows ของ API เท่านั้น);
  **เลือก class** = เลือก class ที่จะวาดด้วย chip (ชื่ออย่างเดียว เช่น "คน (person)") — chip ใช้เฉพาะในมุมมองนี้;
  ไฟ/ควัน/คนล้มถูกวาดในทั้งสองมุมมอง; ถ้าไม่พบคนหรือปิด "ตรวจ PPE" จะใช้มุมมอง class
- **"ตรวจ PPE" (9.4.7, ค่าเริ่มต้นเปิด):** ปิดแล้วซ่อน alert PPE จากสรุป ตาราง และสีกล่อง (เช่น ฉากที่ไม่ใช่งานก่อสร้าง) — การแสดงผลเท่านั้น
- **slider "แสดงเฉพาะคะแนน ≥ X"** (ค่าต่ำสุด = threshold ต่ำสุดของ API) — กรองการแสดงผลเท่านั้น ไม่ส่งไป API
  ไม่เปลี่ยน threshold และไม่เปลี่ยนผล PPE
- **กล่องอ่านง่าย (9.3):** label ขนาดคงที่ ~11.5 CSS px ไม่ขึ้นกับความละเอียดภาพ, เส้นบาง, label อยู่ในกรอบภาพ,
  label ของ person วางเหนือ/ใต้กล่องก่อนเพื่อไม่บังหน้า; วิดีโอและภาพใช้โค้ดวาดเดียวกัน (`drawScene()`)
- **แผงขวา "ผลตรวจ…"** (ภาพนิ่งและวิดีโอ): จำนวนวัตถุในเฟรม/ภาพนี้ + ตาราง PPE แบบย่อ (แถวที่มี alert ขึ้นก่อน,
  hover/focus แถวจะไฮไลต์กล่องของคนนั้น)
- **รายละเอียดทางเทคนิค** (`<details>` ปิดไว้ก่อน): model, mode, sample_fps, fps, schema_version, threshold ต่อ class,
  ppe_min_confidence, กฎสรุปวิดีโอ, สถานะ API (device / โมเดล / ปุ่มรีเฟรช) และผลรายช่วงของ Stage 2
  รวมถึงเวลาวัด decoder, YuNet, YOLO, X3D และเวลารวมจาก API (ตัวเลขขึ้นกับฮาร์ดแวร์/codec)
  Track IDs ถูกสร้างจากกล่อง person ที่ตรวจพบ จึงอาจซ้ำตามกล่องซ้ำและไม่ใช่การยืนยันอัตลักษณ์บุคคล
- **ป้าย "ผลจากโมเดลจริง — pilot"** แสดงเฉพาะเมื่อ response มี `is_model_output === true` พร้อม `disclaimer` จาก API
  (chip บน topbar "หน้าเรียก API จริง · pilot" เป็นแค่ป้ายบอกหน้า)
- **Error:** `{error:{code,message}}` → ข้อความภาษาไทยตาม `code` (+ ข้อความต้นฉบับ); เชื่อมต่อไม่ได้ →
  "เชื่อมต่อ API ไม่ได้ — รัน backend ก่อน"
- **ความปลอดภัย:** ข้อความจาก API เขียนด้วย `textContent` / `fillText` เท่านั้น (ไม่ใช้ `innerHTML`);
  `analyze.js` ไม่ใช้ `Math.random` และไม่อ่าน mock data ของ `index.html`

**ไฟล์วิดีโอทดสอบที่เบราว์เซอร์เล่นได้:** OpenCV `VideoWriter` ด้วย fourcc `'avc1'` ใน `.mp4` ได้ H.264 ที่ Chrome
เล่นได้ (ในเครื่องนี้ OpenCV เตือนว่าโหลด OpenH264 DLL ไม่ได้ แต่ไฟล์ที่ได้เป็น h264 และเล่นได้);
`'mp4v'` เล่นใน Chrome ไม่ได้ (ใช้ทดสอบ fallback ได้)

## โครงสร้างโค้ดปัจจุบัน

- `index.html`: โครงหน้าและ router `go(page)`; ส่วนจอมอนิเตอร์หลายกล้องเดิมถูกถอดจาก DOM เมื่อเริ่มเว็บและไม่ใช้เป็นแหล่งข้อมูลเดโม

- `logs.js`: อ่านประวัติจาก `/api/logs` และบันทึกสถานะผ่าน PATCH
- `notifications.js`: อ่าน `/api/notifications` ทุก 2 วินาทีเมื่อเปิดเว็บ แสดง popup ใหม่และเปิดรายละเอียดใน Logs

## Dashboard จากประวัติจริง

เลือกวันนี้, 7 วันตามปฏิทินรวมวันนี้ หรือทั้งหมด โดยใช้ Asia/Bangkok จำนวนรายการคือแถวสรุปต่อรอบ/ประเภทผล/โมเดล รวม Non-fight และ PPE จากกฎ ไม่ใช่จำนวนเหตุ คน กล้อง หรือจำนวนกล่องทั้งหมด

กราฟใช้ `recorded_at` ครั้งแรก ไม่ใช่เวลาในวิดีโอ และแสดง 7 วันรวมวันนี้ภายในช่วงที่เลือก กรณีเลือกทั้งหมด ยอดรวมและประเภทผลครอบคลุมทั้งหมด แต่กราฟรายวันแสดงเฉพาะ 7 วันล่าสุด ต่างจากตัวกรอง 7d ของ Logs ที่เป็นช่วงย้อนหลัง 7 × 24 ชั่วโมง

จำนวนรอบนับตามเวลาเริ่มรอบ รวมรอบที่ไม่พบผลตรวจจับ ส่วนสถานะ Live เป็นเซสชันล่าสุดของ backend process นี้ แยกจากช่วงประวัติ หลัง restart ประวัติยังอยู่แต่สถานะ Live กลับเป็นยังไม่มีเซสชัน หากฐานข้อมูลใช้ไม่ได้จะล้างยอด/กราฟเก่าและแสดง error สถานะ Live ที่อ่านได้ยังแสดงแยกกัน

## ประวัติผลตรวจจับจริง

ฐานข้อมูลเริ่มต้นคือ `data/local/cctv_safety.sqlite3` ซึ่ง Git ignore ไว้ สร้างเมื่อ backend ใช้งานประวัติครั้งแรก เปลี่ยนตำแหน่งได้ด้วย `CCTV_EVENTS_DB_PATH` และใช้หนึ่ง backend process ต่อฐานข้อมูล

เปิดเมนู Alert / Logs หลังวิเคราะห์ไฟล์ หรือกดรีเฟรชประวัติ ข้อมูลไม่มีการสร้างย้อนหลังจาก mock เดิม การวิเคราะห์ซ้ำสร้าง run ใหม่ ส่วนผลชนิดเดียวกันภายใน run เดียวรวมจำนวน observations และคะแนนสูงสุด แสดงเวลาในวิดีโอแยกจากเวลาบันทึก Asia/Bangkok

สถานะรอตรวจสอบ/รับทราบ/ปิดรายการไม่ยืนยันเหตุจริง ไม่มีผู้รับผิดชอบสมมติ ปัจจุบันมีการแจ้งเหตุสงสัยภายในเว็บตามหัวข้อถัดไป ดู API และข้อจำกัดที่ [สัญญา API](../docs/web_api_contract.md) และ [รายงานประวัติ](../docs/presentation/history-verification.md)

## แจ้งเหตุสงสัยภายในเว็บ

ปุ่มเหตุสงสัยบนแถบบนเปิดรายการแจ้งที่บันทึกจริง จำนวนบนปุ่มเป็นรายการแจ้งทั้งหมด ไม่ใช่จำนวนที่ยังไม่อ่าน เมื่อมีรายการใหม่หลังเปิดเว็บจะแสดง popup พร้อมปุ่มเปิดประวัติ OBS ที่เกี่ยวข้อง ปิด popup เป็นการซ่อนข้อความเท่านั้น ให้รับทราบ/ปิดรายการจาก Logs เพื่อหยุดแจ้งซ้ำของผลสรุปเดิม

เกณฑ์ปัจจุบัน: Fall/Fire/Smoke/PPE-derived/Fall-Fight-conflict คะแนนอย่างน้อย 0.5 และ Fight อย่างน้อย 0.7 ไม่แจ้งจาก Person/Helmet/Vest/Non-fight เกณฑ์นี้เป็น heuristics ของต้นแบบ ส่วนคะแนน PPE เป็น person confidence ประกอบกฎ ไม่ใช่ความน่าจะเป็นว่าไม่สวมอุปกรณ์

ช่วงพัก 30 วินาทีใช้เวลาประมวลผล/บันทึกจริงต่อแถวประวัติ (run/type/model) และคงอยู่หลัง restart ไม่ใช้เวลาในวิดีโอหรือรับรองว่าเป็นคนละเหตุ วิเคราะห์ซ้ำสร้าง run ใหม่และแจ้งได้ใหม่ตามเกณฑ์ รายการที่รับทราบ/ปิดแล้วจะไม่สร้างแจ้งใหม่จนเปิดกลับและพบผลเข้าเกณฑ์อีกครั้ง

ฐานข้อมูล v1 ย้ายเป็น v2 อัตโนมัติโดยรักษาประวัติและสถานะเดิม ไม่สร้างการแจ้งย้อนหลังจากข้อมูลเก่า หน้าเว็บแสดงล่าสุด 20 รายการ และไม่ popup รายการเก่าเมื่อ reload ไม่มี browser Push, เสียง, email หรือ LINE ดู [รายงานงาน 4](../docs/presentation/notifications-verification.md)

## ค่าตั้งการวิเคราะห์ที่บันทึกได้

เปิดตั้งค่าระบบ แก้ confidence ทั้ง 6 คลาส, NMS IoU, ขนาดภาพ, max detections, Fight threshold และ Tracking แล้วกดบันทึก ค่าเก็บใน SQLite schema 3 พร้อม revision และเวลา เมื่อเปิดโปรแกรมใหม่ยังโหลดกลับได้ ค่าเริ่มต้นเดิมใช้เมื่อยังไม่มีการบันทึก การใส่ค่าเริ่มต้นในฟอร์มยังไม่เปลี่ยน backend จนกดบันทึก

ค่าใหม่มีผลกับคำขอวิเคราะห์หรือ Live session ถัดไป งานที่เริ่มแล้วใช้ snapshot เดิมจนจบ API ส่ง analysis_settings และ settings_revision ที่ใช้อ้างอิงกลับมา หากแก้พร้อมกันจากสองหน้าต่าง revision เก่าจะได้ 409 ให้โหลดค่าปัจจุบันก่อนบันทึกใหม่ ค่าผิดช่วง/ชนิด/ชื่อ field จะไม่ถูกบันทึก

Upload & Analyze เลือกใช้ค่าที่บันทึกโดยค่าเริ่มต้น หากยกเลิก checkbox นี้จะใช้ค่าขั้นสูงในฟอร์มเฉพาะคำขอนั้นและไม่บันทึกทับค่าระบบ Live upload ใช้ค่าที่บันทึก ส่วน JSON Live start รองรับ override ตามสัญญา API ค่าความเป็นส่วนตัว การเลือก device และเกณฑ์แจ้งเหตุสงสัยเป็นคนละส่วนกับค่าที่บันทึกหน้านี้ ดู [รายงานงาน 5](../docs/presentation/settings-verification.md)

แถบด้านข้างและ Dashboard แสดงแบรนด์ AEGIVIS; Dashboard วางโลโก้เต็มพร้อมสโลแกน “AI-Powered Safety Shield” เรื่องหลักเริ่มที่ **จุดรับสินค้า · PPE ไม่ครบ · สมมติ** เป็นฉากโรงงานวาดขึ้นพร้อมคะแนนกำหนดไว้ ไม่ได้เปิดกล้องหรือรันโมเดล Live แสดงว่ากำลังรอเหตุการณ์สาธิต และเมื่อเริ่มเล่นจะเดินเรื่อง Live → แจ้งเตือน → Logs → Dashboard ตามเวลา 10/20/45/90 วินาที
